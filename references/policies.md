# 策略与实体

策略版本：2026-10-26.2。所有模式均在本地处理，且在导出前要求本地人工复核。

## 三个处理目的

| 模式 | 默认行为 | 需要人工确定 |
|---|---|---|
| `ai` | 处理身份、联系方式、案件/合同/项目标识、词典机密及识别出的间接线索；默认保留金额、日期与法院名称 | 身份组合、商业秘密边界及分析所需细节 |
| `external` | 与 `ai` 采用相同保守基础规则；审阅与后续恢复用途单独标记在策略中 | 给谁审阅、应保留的主体、后续编辑恢复要求 |
| `public` | 在前述规则上额外识别完整中文日期和金额，不保留法院识别的特殊豁免 | 公开范围、独特案情、职业与关系组合、是否有合法公开依据 |

`ai`/`external` 当前识别逻辑相同，不夸大模式间算法差异。`public` 是更严格的通用分享模板，并不是裁判文书公开自动合规流程；未实现 k 匿名或主体重识别概率计算。

## 实体与识别来源

- 确定性规则：中文手机、座机、邮箱、身份证候选及校验码、银行卡 Luhn 校验、字段上下文账户、统一社会信用代码候选、案号、合同编号、地址上下文、项目代号、产权号、车牌、凭证上下文。
- 法律上下文规则：原被告/证人/法定代表人等角色后的姓名候选、未成年人、健康描述、唯一创始人、股权比例和部分亲属关系线索。规则用于召回候选，不足以做完整关系推理。
- 中文 spaCy 模型：PERSON、ORG、GPE、LOC。其训练语料不是专用法律语料，不能称为法律专用高精度 NER；英文姓名不在该模型的验收承诺中。
- 本地词典与手动补充：企业/案件机密、别称、证据编号及报告中特定领域实体。模型只能增加候选，不能否决确定性规则或人工决定。
- 信用代码仅做候选格式识别，身份证号校验失败也不直接丢弃；置信度 `1.0/0.75` 是规则/模型来源标识，未做概率校准。

## 本地案件词典

在用户本机编辑 UTF-8 JSON，不要把真实词典内容交给 Agent。示例仅使用虚构数据：

```json
{
  "terms": [
    {"text": "赵测试", "kind": "PERSON", "entity": "client-1"},
    {"text": "赵先生", "kind": "PERSON", "entity": "client-1"},
    {"text": "蓝鲸测试项目", "kind": "SECRET", "entity": "project-1"}
  ],
  "allow": ["演示公开公司"]
}
```

可用类别：PERSON、ORG、ADDRESS、PHONE、EMAIL、ID、ACCOUNT、CREDIT_CODE、CASE、CONTRACT、PROJECT、SECRET、VEHICLE、PROPERTY、HEALTH、MINOR、DATE、AMOUNT、ROLE、QUASI、CREDENTIAL。

规则优先级：显式词典 → 确定性规则 → 本地 NER。重叠时保留较长候选；人工可更正。词典冲突或重叠不能被当作已经消除所有风险。

同文件、同类别、同字面值使用稳定占位符；旧 CLI 任务跨文件默认不自动合并；2.0 工作台任务在用户确认的同一案件作用域内复用同字面占位符。给词条显式设置相同 `entity` 可进一步明确身份作用域。不同别称保留各自精确映射，不把恢复稿全部改成同一写法。同名不同人无法仅凭字面值判断，必须在复核中区分；2.0 可以在命中项中填写不同的“同名区分编号”，或使用带上下文词条 / 拆任务；不自动完成共指消解。

白名单只是候选保留建议，不等于外发授权。高风险类别命中白名单时仍默认遮盖，标记冲突；任何人工保留必须填写理由，并计入报告。即使用户保留，内容仍可能属于个人信息。

## 语义保护

占位符只替换命中范围；条款编号和非敏感段落不重写。长占位符可能改变分页，不承诺像素级 Office 保真。需要保留特定日期、金额、法院时，由用户本地复核决定并记录理由。若案件依赖独特股权、职业、案情或家属身份，即使已打掉姓名也应继续标记上下文线索。

2.0 场景、接收对象、金额日期选项与学生副本的精确行为见 [场景与交付](scenarios-and-delivery.md)。自由背景是备注，不会悄悄变成额外代码或披露授权。
