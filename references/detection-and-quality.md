# 检测与质量控制

## 检测路径

对结构化文本先做 Unicode NFKC 单字符规范化，保留可回映的原字符偏移；再并行采集确定性格式/字段规则、案件词典、中文本地 NER、表格表头语境和用户手动选区。检测来源保存在候选记录中，重叠候选按词典与较长范围优先去重。所有高风险候选仍须由用户逐文件复核；分数是规则来源标签，不是经过校准的正确概率。

本版补强了常见法律当事人角色和联系人标签；增加姓名后接起诉、签署、提交等法律动作时的候选规则；地址字段扩展到居住地、户籍地址、注册地址、收件地址等；对“省/市/区 + 道路/门牌”结构增加独立地址候选。NER 地址中夹有空格时先压缩空白再验证地名特征。规则模式仍不能替代中文 NER，必须保留规则模式提示与额外人工确认。

姓名启发式仅针对有限常见中文姓氏和明确法律语境，不推断任意无上下文人名，也不做共指或同名消歧。地址形状规则只产生候选，不表示字段边界已被证明。对候选范围过宽、候选互相重叠或文件语义复杂的情形，要求本地用户收窄、取消或手工补充，不静默扩大遮盖范围。

## Office 遮盖与恢复

DOCX/XLSX/PPTX 的脱敏副本以统一 `***` 显示遮盖内容，避免把内部 token 误认为乱码或把实体类别暴露给接收者。每个遮盖位置对应的内部 token、原文映射和单元/字符偏移只留在口令加密保险库。TXT/MD/CSV/TSV/JSON/XML/LOG/EML 仍用完整不透明占位符，以支持精确编辑恢复。

Office 编辑后恢复要求星号遮盖符仍处于相同 OOXML 文本单元及字符偏移，并且数量完整。缺失、复制、移动标记、重排导致单元编号改变或歧义标记均失败关闭，不生成恢复稿；取回原件仍按字节恢复。即使恢复成功，仍需人工检查业务语义、格式及元数据。

## 双平台运行

Windows/macOS 共用一个 Python 检测与格式核心。OS 差异封装在 `platform_support.py`：路径/长路径处理、原子替换、文件权限或 ACL、外部 OCR/转换工具发现、子进程窗口、文件管理器、时区和单实例锁。安装启动器与 Python 版本/模型依赖分平台适配；识别逻辑不按操作系统分叉。目标平台没有中文模型、OCR 语言包或必要工具时报告缺失并按格式失败关闭，不改用云端。

每次发布都应在 Windows 和 macOS 各跑同一合成测试集合，并核对启动器、依赖、规则模式告警、保险库读写、中文路径、Office 输出/恢复、残留验证和原件字节恢复。平台模拟测试只能验证被模拟的分支；不能将其描述为在真实 Windows/macOS 上完成的现场验证。

## 对 ZonKey 的方法性借鉴

ZonKey README 描述桌面壳、React 前端、本机 FastAPI 桥接与 Python 引擎的分层，脱敏引擎将矢量文本、OCR、规则/词表和视觉/印章线索分通道处理；其文档 PDF 流水线先收集命中再合并候选并执行抹除，OCR 模块返回文字框，macOS 工作流在 Intel 与 Apple Silicon runner 上分别构建。可借鉴的原则是检测通道职责清楚、候选融合可审计、先定位再处理、跨平台把系统差异集中到适配层，并把处理后验证纳入流水线。

本技能没有复制 ZonKey 的程序代码、桌面架构、PDF 页级几何融合或产品功能；这里的实现依然是法律文档工作流：本地 spaCy NER/规则/表头与案件词典候选、人工复核、Office OOXML 或图像/PDF 格式转换、加密映射与恢复、严格残留验证。PDF 全页图像重建等产品策略不等于本技能的普遍最佳做法，因此不直接照搬。

## 安全测试要求

1. 只用显式合成身份、地址、凭证和虚构文件测试；真实案件不得进入自动化 GUI 截图、测试上传或模型提示。
2. 用合成 DOCX 制造跨 Word run、表格、批注、页眉、隐藏内容及修订片段，并确认导出只出现 `***`，原文不在脱敏文件、报告或日志中。
3. 用合成姓名/地址字段、普通法律叙述、带空格地址、同名与否定/普通词做正负向测试；汇总召回例和误报例，不报告未经设计的准确率。
4. 每种输出逐文件核对状态、格式可打开性、占位符可见形态、文本残留、完整原件恢复和编辑后冲突行为。`CHECKED` 仅表示这次机械验证和本地复核链通过。
5. 保留 Windows/macOS CI 结果的测试数与失败用例名；不将原文样本或真实路径放进公开报告。
